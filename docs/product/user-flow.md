# SwimFind User Flow

SwimFind MVP의 핵심 사용자 흐름과
예외 상황에서의 화면 전환 원칙을 정의한다.

화면 이동, 로그인 복귀, 검색 조건 유지,
오류 처리, 상태별 다음 행동을 구현할 때 이 문서를 참고한다.

---

## 1. User Flow Goal

SwimFind의 핵심 도달점은 다음과 같다.

```text
오늘 어디에서 수영할지 결정할 수 있는 상태
```

사용자는 가능한 한 적은 단계로:

```text
수영장을 찾고
→ 오늘 이용할 수 있는지 확인하고
→ 필요한 시간과 가격을 확인하고
→ 방문 여부를 결정
```

할 수 있어야 한다.

---

## 2. Overall Flow

가장 중요한 사용자 흐름:

```text
홈
→ 지역 또는 수영장 검색
→ 검색 결과
→ 수영장 상세
→ 오늘 자유수영 시간 / 가격 / 위치 확인
→ 방문 결정
```

관심 수영장은 재검색 없이
바로 상세 확인으로 이어진다.

후기와 시설 정보는
방문 판단을 보조한다.

잘못된 정보는 사용자 제보 후
운영자 검토를 거쳐 수정한다.

---

## 3. Access Rules

로그인 없이 이용:

```text
홈
검색 결과
수영장 상세
후기 조회
```

로그인이 필요한 행동:

```text
관심 수영장 저장
후기 작성
정보 제보
마이페이지
```

로그인 때문에
수영장 탐색과 정보 열람이 막히지 않아야 한다.

---

## 4. Definition of "Today"

국내 수영장은:

```text
Asia/Seoul
```

기준으로 날짜와 시간을 계산한다.

"오늘 이용 가능"을 판단할 때는
시설 운영시간과 자유수영 시간을 구분한다.

확인된 임시 휴관이나 운영 변경이 있으면
정기 시간표보다 우선한다.

시간표상 운영 중이라고 해서
실제 입장을 보장하지 않는다.

가능하면 다음 정보를 함께 보여준다.

```text
남은 회차
입장 마감
이용 조건
정보 확인일
```

실시간 입장이 확정된 것처럼 표현하지 않는다.

---

# Core User Flow 1

## 오늘 자유수영할 수영장을 찾는 사용자

### User Situation

사용자는 오늘 수영하고 싶지만
아직 방문할 수영장을 정하지 않았다.

가까운 후보 중:

```text
시간
가격
위치
```

가 맞는 곳을 빠르게 찾고 싶어 한다.

---

## 5. Discovery Flow

```text
홈
→ 지역 또는 수영장 검색
→ 오늘 자유수영 정보가 있는 검색 결과
→ 수영장 선택
→ 시간과 가격 확인
→ 필요 시 시설 / 후기 확인
→ 방문 결정
```

---

### Step 1. Search

홈에서 다음 방법으로 탐색한다.

```text
지역 선택
수영장 이름 검색
현재 위치 사용
```

현재 위치 사용이 불가능해도
지역을 직접 선택할 수 있어야 한다.

---

### Step 2. Compare Search Results

검색 결과에서 다음 정보를 비교한다.

```text
수영장 이름
위치
오늘 자유수영 상태
남은 자유수영 회차
가격
정보 최종 확인일
```

미확인 정보는
확정된 정보와 구분해서 표시한다.

---

### Step 3. Check Pool Detail

수영장 상세 상단에서 다음을 확인한다.

```text
오늘 자유수영 상태
휴관 여부
회차별 시간
입장 마감
가격
이용 대상 / 조건
```

가격이나 이용 조건을 모르면
추정값 대신 미확인 상태로 보여준다.

---

### Step 4. Check Supporting Information

필요하면 다음 정보를 추가로 확인한다.

```text
시설
FAQ
후기
공식 홈페이지
```

기본 위치와 공식 안내 링크는
상세 페이지에서 쉽게 찾을 수 있어야 한다.

---

### Step 5. Decide

사용자가 방문할 곳을 결정하면
다음 행동으로 이어질 수 있다.

```text
길찾기
공식 홈페이지 확인
관심 수영장 저장
```

서비스는 실제 방문 완료까지
확정했다고 간주하지 않는다.

---

### Completion Criteria

사용자가 다음 정보를 이해한 상태:

```text
오늘 이용 가능한가?
언제 이용 가능한가?
가격은 얼마인가?
조건은 무엇인가?
```

그리고 이를 바탕으로
방문 여부를 판단할 수 있다.

---

# Core User Flow 2

## 관심 수영장을 다시 확인하는 사용자

### User Situation

사용자는 이전에 저장한 수영장을
오늘 이용할 수 있는지 다시 확인하려고 한다.

---

## 6. Favorite Revisit Flow

```text
홈 또는 마이페이지
→ 관심 수영장 목록
→ 오늘 상태 확인
→ 수영장 상세
→ 남은 회차 / 변경 사항 확인
→ 방문 결정
```

관심 목록에서는
저장 당시 데이터가 아니라
현재 제공되는 정보를 보여준다.

---

### When Available

```text
관심 수영장 목록
→ 오늘 상태 확인
→ 상세 진입
→ 남은 회차 확인
```

---

### When Closed or Ended

```text
휴관 또는 오늘 일정 종료
→ 다른 관심 수영장 확인
또는
→ 같은 지역의 다른 수영장 검색
```

저장된 수영장이 없으면
수영장 탐색으로 안내한다.

---

### Logged-out User

관심 목록 접근이 필요한데 로그인하지 않았다면:

```text
관심 목록 진입
→ 로그인
→ 관심 목록으로 복귀
```

---

### Favorite Removal

관심 수영장을 해제하면
성공 여부를 즉시 알려준다.

실패하면 기존 상태를 유지한다.

---

### Completion Criteria

사용자가 다시 검색하지 않고
저장한 수영장의 오늘 이용 조건을 확인할 수 있다.

---

# Core User Flow 3

## 후기를 확인하는 사용자

### User Situation

사용자는 공식 정보만으로 확인하기 어려운:

```text
청결도
시설 상태
혼잡 경험
실제 이용 경험
```

을 알고 싶어 한다.

---

## 7. Review Reading Flow

```text
수영장 상세
→ 후기 영역
→ 후기 목록
→ 후기 내용 확인
→ 필요 시 작성자 프로필 / 다른 후기 확인
→ 수영장 상세로 복귀
```

후기는 로그인하지 않아도 읽을 수 있다.

---

### Review Context

가능하면 다음 정보를 함께 보여준다.

```text
작성일
방문 시점
작성자
이용 경험
```

후기에 적힌 혼잡도는
그 사용자의 당시 경험이다.

현재 실시간 혼잡도처럼 표시하지 않는다.

---

### No Reviews

후기가 없다면:

```text
아직 작성된 후기가 없어요.
```

같은 안내와 함께
후기 작성 진입점을 제공할 수 있다.

후기가 없어도
수영장의 기본 이용 정보는 계속 볼 수 있어야 한다.

---

### Completion Criteria

사용자가 공식 정보 외에
방문 판단에 도움이 되는 실제 이용 경험을 확인할 수 있다.

---

# Core User Flow 4

## 후기를 작성하는 사용자

## 8. Review Writing Flow

```text
수영장 상세
→ 후기 작성
→ 로그인 확인
→ 후기 입력
→ 입력 검증
→ 후기 등록
→ 작성한 후기 확인
```

---

### Logged-out User

비로그인 사용자가 후기 작성을 선택하면:

```text
후기 작성 선택
→ 로그인
→ 원래 수영장의 후기 작성 화면으로 복귀
```

로그인 성공만으로
후기가 자동 제출되면 안 된다.

사용자가 내용을 다시 확인한 뒤
직접 등록한다.

---

### Review Form

작성 화면에서는
어느 수영장에 대한 후기인지 명확히 보여준다.

주요 입력 예:

```text
후기 내용
방문 시점
청결도
시설 상태
레인 혼잡도
이미지
```

등록 전에 필수값을 확인한다.

오류는 가능한 한
해당 입력 항목 가까이에 표시한다.

---

### Submit Failure

후기 등록이 실패하면:

```text
입력 내용 유지
이미지 선택 상태 유지
오류 안내
재시도 제공
```

을 우선한다.

사용자가 처음부터 다시 작성하게 하지 않는다.

---

### Successful Submission

정상 등록 후에는
성공 여부를 분명하게 알려준다.

예:

```text
작성한 후기 확인
내 후기 이동
작성자 프로필 이동
```

중 하나로 연결할 수 있다.

중복 제출을 방지한다.

---

### Completion Criteria

사용자는 자신의 후기가
정상적으로 등록되었음을 확인할 수 있다.

---

# Supporting User Flow

## 잘못된 수영장 정보 제보

## 9. Pool Report Flow

```text
수영장 상세
→ 정보 수정 제보
→ 로그인 확인
→ 제보 작성
→ 제출
→ 접수 완료
→ 운영자 검토
→ 승인 또는 반려
```

---

### Report Categories

제보 항목 예:

```text
자유수영 시간
가격
휴관
시설
기타 정보
```

사용자는:

```text
현재 정보
잘못된 내용
수정 제안
근거
```

를 확인하거나 입력할 수 있어야 한다.

공식 홈페이지나 공지 링크 등
근거를 첨부할 수 있다.

---

### Submission

제보 제출 완료 시
즉시 공식 정보로 반영되지 않는다는 점을 알려준다.

```text
접수
→ 운영자 검토
→ 승인 / 반려
```

---

### Submit Failure

제보 제출이 실패하면
작성 내용을 유지하고 재시도를 제공한다.

---

### Operator Review

운영자는:

```text
사용자 제보
공식 자료
현재 데이터
```

를 비교한다.

승인 시 관련 공식 정보와 확인일을 수정한다.

근거 부족 또는 사실 불일치 시
반려 사유를 남긴다.

---

### Report Status

처리 상태:

```text
검토 대기
승인
반려
```

검토 중인 제보를
검증된 공식 정보처럼 노출하지 않는다.

---

### Completion Criteria

제보가 정상 접수되고
운영자 검토 결과에 따라 처리된다.

---

# Exception Flows

## 10. Exception Handling Principle

예외 화면에는 항상 다음 세 가지를 제공한다.

```text
현재 상태
왜 이런 상태인지
사용자가 다음에 할 수 있는 행동
```

가능하면 사용자가 이전에 입력한:

```text
검색 조건
폼 작성 내용
목록 위치
```

를 유지한다.

---

## 11. 오늘 자유수영 없음 / 모든 회차 종료

다음을 구분한다.

```text
휴관
자유수영 미운영
오늘 일정 없음
모든 회차 종료
정보 미확인
```

오늘 회차가 있었더라도
현재 시각에 모두 끝났다면
오늘 이용 가능한 수영장으로 안내하지 않는다.

흐름:

```text
오늘 이용 불가 확인
→ 같은 지역의 다른 수영장 탐색

또는

→ 다음 운영 일정 확인
→ 후보 재선택
```

안내 예:

```text
오늘 자유수영 일정이 모두 종료되었어요.
다른 수영장을 확인해 보세요.
```

다음 일정은 확인된 정보가 있을 때만 제공한다.

---

## 12. Search Result Empty

검색 결과가 없다면
현재 적용된 조건을 보여준다.

```text
검색어
지역
필터
```

다음 행동을 제공한다.

```text
검색어 수정
조건 해제
지역 변경
조건 전체 초기화
```

흐름:

```text
결과 없음
→ 검색 조건 수정 또는 완화
→ 재검색
```

안내 예:

```text
선택한 조건에 맞는 수영장이 없어요.
지역이나 검색 조건을 바꿔 보세요.
```

실제로 검색 결과가 없는 상황과
네트워크/서버 조회 실패를 구분한다.

---

## 13. Login Required

비로그인 상태에서 다음 행동을 선택하면:

```text
관심 저장
후기 작성
정보 제보
```

로그인이 필요함을 안내한다.

흐름:

```text
로그인 필요 행동
→ 로그인
→ 원래 수영장 / 진행 화면 복귀
```

로그인을 취소하면
기존 화면으로 돌아간다.

로그인 성공 자체가
기존 폼의 자동 제출을 의미하지 않는다.

---

## 14. Information Unverified

시간표가 없거나
최신 여부가 확인되지 않은 경우:

```text
정보 미확인
```

으로 표시한다.

다음처럼 처리하지 않는다.

```text
정보 없음
→ 오늘 자유수영 없음
```

또는:

```text
정보 없음
→ 이용 가능하다고 추정
```

둘 다 금지한다.

흐름:

```text
미확인 상태 확인
→ 정보 확인일 / 출처 확인
→ 공식 안내 확인

또는

→ 다른 수영장 탐색

또는

→ 정보 제보
```

---

## 15. Information Conflict

공식 정보와 사용자 제보가 다르면
사용자 제보를 바로 공식 정보로 대체하지 않는다.

```text
제보 접수
→ 운영자 검토
→ 확인
→ 공식 데이터 수정
```

확인된 정보와 미확인 정보를 구분한다.

오래된 정보에는
최종 확인일을 표시한다.

---

## 16. Location Permission Denied

현재 위치 권한이 거부되거나
위치를 확인할 수 없다면:

```text
현재 위치 탐색 실패
→ 지역 직접 선택
```

으로 이어진다.

현재 위치 권한 허용을
서비스 이용의 필수 조건으로 만들지 않는다.

---

## 17. Network Error

조회 중 네트워크 오류가 발생하면:

```text
조회 실패 안내
→ 같은 조건으로 다시 시도
```

할 수 있어야 한다.

검색 결과 0건과
네트워크 오류를 같은 화면으로 처리하지 않는다.

---

## 18. Mutation Failure

관심 저장, 후기 작성, 제보 제출 등
변경 작업이 실패하면:

```text
성공 메시지를 표시하지 않는다.
```

가능하면 기존 입력과 상태를 유지한다.

예:

```text
후기 입력 내용 유지
제보 입력 내용 유지
관심 상태 원복
```

---

## 19. Back Navigation

검색 결과에서 상세로 이동한 후
뒤로 돌아오면 가능한 한:

```text
검색어
지역
필터
목록 위치
```

를 유지한다.

사용자가 같은 탐색 작업을
처음부터 반복하지 않게 한다.

# Conversion Points

## 20. Key Conversion Points

가장 중요한 전환은:

```text
수영장 상세
→ 오늘 이용 조건 확인
```

이다.

---

### Discovery → Detail

```text
검색 결과
→ 수영장 상세
```

후보 정보가 사용자의 관심을 끌었는지 확인하는 단계다.

---

### Detail → Today's Information

```text
상세 진입
→ 오늘 상태 / 회차 / 가격 / 조건 확인
```

단순 상세 진입과
오늘 이용 정보를 실제 확인한 행동을 구분할 수 있다.

---

### Today's Information → Visit Intent

```text
오늘 이용 정보 확인
→ 길찾기 또는 공식 안내 선택
```

이는 실제 방문 완료가 아니라
방문 의도의 보조 지표로 본다.

---

### Detail → Favorite → Revisit

```text
상세
→ 관심 저장
→ 관심 목록
→ 다시 상세 확인
```

관심 수영장이
재탐색 비용을 줄이는지 확인한다.

---

### Review Start → Review Complete

```text
후기 작성 시작
→ 등록 완료
```

작성 시작 대비 완료율과
오류 / 이탈 구간을 확인할 수 있다.

---

### Report Submitted → Review Complete

제보는 다음을 분리해서 본다.

```text
제보 접수 성공
!=
운영자 검토 완료
```

---

## 21. UX Principles

### Preserve Context

사용자가 작업 중이던 맥락을 가능한 한 유지한다.

예:

```text
검색 조건
폼 입력값
목록 위치
선택한 수영장
```

---

### Do Not Guess

확인되지 않은 정보를
서비스가 임의로 확정하지 않는다.

```text
미확인
→ 미확인으로 표현
```

---

### Always Provide a Next Action

예외 상태에서도
막힌 화면으로 끝내지 않는다.

예:

```text
검색 결과 없음
→ 조건 변경

오늘 일정 종료
→ 다른 수영장 탐색

위치 권한 거부
→ 지역 직접 선택

정보 미확인
→ 공식 정보 확인 / 다른 수영장 탐색 / 제보
```

---

### Do Not Overstate Availability

시간표상 운영 중이라고 해서:

```text
지금 바로 입장 가능
```

하다고 보장하지 않는다.

다음 정보를 함께 고려한다.

```text
회차
입장 마감
이용 대상
휴관
운영 변경
```

---

## 22. Core Completion Goal

SwimFind의 핵심 User Flow가 완료되었다고 볼 수 있는 상태:

```text
사용자가
오늘 이용 가능한 후보를 찾고

→ 이용 시간
→ 가격
→ 조건
→ 위치

를 이해한 뒤

오늘 어디에서 수영할지
결정할 수 있다.
```
