# SwimFind Information Architecture

SwimFind MVP의 화면 구조와
각 화면의 목적, 핵심 정보, 주요 행동, 예외 처리를 정의한다.

페이지 또는 주요 화면 컴포넌트를 구현할 때
이 문서를 기준으로 확인한다.

화면 간 이동 순서는 `user-flow.md`,
MVP 범위는 `mvp.md`를 함께 참고한다.

---

## 1. IA Overview

MVP의 핵심 화면은 다음과 같다.

```text
홈
├─ 수영장 검색 결과
│  └─ 수영장 상세
│     ├─ 후기 목록
│     │  └─ 후기 작성
│     ├─ 정보 제보
│     └─ 관심 저장
│
├─ 관심 수영장 목록
│  └─ 수영장 상세
│
├─ 로그인
│
└─ 마이페이지
   ├─ 관심 수영장
   ├─ 내가 작성한 후기
   └─ 내가 제출한 제보
```

핵심 탐색 흐름:

```text
홈
→ 검색 결과
→ 수영장 상세
```

이 세 화면을 가장 먼저 완성한다.

---

# 2. Home

## Purpose

사용자가 다음 기준으로
오늘 이용할 수 있는 수영장을 빠르게 탐색하도록 돕는다.

```text
지역
수영장 이름
현재 위치
```

---

## Entry Points

```text
서비스 첫 방문
로고 선택
상단 또는 하단 홈 메뉴
```

---

## Core Information

홈 화면에서 제공할 수 있는 정보:

```text
현재 위치 기반 탐색 안내
지역 선택 및 검색
수영장명 검색창
현재 위치 주변의 오늘 자유수영 가능 수영장
오늘 자유수영이 가능한 추천 수영장
관심 수영장
최근 검색 지역 또는 수영장
```

모든 영역을 최초 버전에서 반드시 동시에 구현할 필요는 없다.

핵심은 사용자가 홈에서
수영장 탐색을 바로 시작할 수 있는 것이다.

---

## Primary Actions

사용자가 할 수 있어야 하는 행동:

```text
현재 위치 사용 허용
주변 수영장 탐색
지역 직접 선택
수영장명 검색
추천 수영장 상세 진입
주변 수영장 상세 진입
관심 수영장 목록 이동
검색 지역 변경
```

---

## Exceptions

### Location Permission Denied

```text
현재 위치 확인 실패
→ 지역 직접 선택 제공
```

위치 권한을 허용하지 않아도
서비스의 핵심 탐색 기능을 사용할 수 있어야 한다.

---

### No Available Pools Nearby

현재 위치 주변에
오늘 이용 가능한 수영장이 없다면:

```text
검색 반경 확대
다른 지역 선택
전체 수영장 탐색
```

등의 다음 행동을 제공한다.

---

# 3. Pool Search Results

## Purpose

사용자가 검색 조건에 맞는 수영장을 비교하고
방문 후보를 선택하도록 돕는다.

---

## Entry Points

```text
홈에서 지역 검색
홈에서 수영장명 검색
현재 위치 기반 탐색
관심 수영장 목록에서 지역 탐색
```

---

## Core Information

검색 화면에서는 현재 검색 조건을 명확히 보여준다.

```text
검색어
선택한 지역
적용된 필터
```

각 수영장 결과에서 보여줄 핵심 정보:

```text
수영장 이름
위치
오늘 자유수영 상태
남은 자유수영 회차
또는 다음 이용 가능 시간
가격 정보
정보 최종 확인일
```

---

## Pool Result Card

최소한 다음 정보가 포함되어야 한다.

```text
대표 이미지
수영장 이름
위치
오늘 자유수영 상태
다음 회차 또는 남은 회차
```

가능하면 다음 정보도 함께 제공한다.

```text
가격
정보 확인일
```

검색 결과만 보고도
사용자가 후보 수영장을 비교할 수 있어야 한다.

---

## Primary Actions

```text
수영장 상세 진입
검색어 수정
지역 변경
필터 적용
필터 해제
검색 조건 초기화
다른 조건으로 재검색
미등록 수영장 등록 요청
```

---

## Search State

검색 조건은 가능하면 URL에 유지한다.

예:

```text
/pools?region=incheon&availableToday=true
```

뒤로 이동하거나 새로고침해도
검색 조건을 복원할 수 있어야 한다.

---

## Empty State

검색 결과가 없다면 다음을 제공한다.

```text
검색어 수정
지역 변경
조건 해제
검색 조건 초기화
수영장 등록 요청
```

안내 예:

```text
선택한 조건에 맞는 수영장이 없어요.
지역이나 검색 조건을 바꿔 보세요.
```

---

## Missing Pool Request

찾는 수영장이 등록되어 있지 않다면
등록 요청으로 연결할 수 있다.

등록 요청에서 확인 가능한 정보 예:

```text
수영장 이름
주소 또는 위치
공식 홈페이지
공식 안내 링크
```

---

```text
이용 가격
이용 조건

휴관 정보
임시 운영 변경

정보 최종 확인일

강습 정보
```

모든 정보를 같은 중요도로 보여주지 않는다.

### Primary Information

상단에서 먼저 보여줄 정보:


### Secondary Information

```text

후기

```

---

## Today's Free Swimming Section

사용자가 가장 먼저 답을 얻어야 하는 질문:

```text
오늘 이 수영장에서 자유수영을 할 수 있는가?
```

표시 정보:

```text

가격
이용 조건
휴관 여부
```

미확인 정보는 추정하지 않는다.

---

## Schedule Section

오늘 외의 이용 계획을 위해
전체 자유수영 일정도 확인할 수 있게 한다.

예:

```text
월
08:00 ~ 08:50
14:00 ~ 14:50

화
08:00 ~ 08:50
...
```

일반 운영시간과
자유수영 시간을 명확히 구분한다.

---

## Facility / FAQ / Lesson Section

정보량을 줄이기 위해
필요하면 다음 형태를 사용할 수 있다.

```text

별도 section
```

특히 자유수영과 강습 정보는
사용 목적이 다르므로 구분해서 보여줄 수 있다.

---

## Review Section

상세에서 다음을 보여줄 수 있다.

```text
후기 개수

최근 후기
후기 전체 보기
후기 작성
```

후기는 방문 판단을 돕는 보조 정보다.

---

## Primary Actions

```text

길찾기
```

# 5. Favorites

## Purpose

사용자가 저장한 수영장의
오늘 이용 가능 여부를 다시 검색하지 않고 확인하도록 돕는다.

---

## Entry Points

```text
홈의 관심 수영장 영역
마이페이지
로그인 후 관심 저장 완료
```

---

## Core Information

```text
저장한 수영장 목록
오늘 자유수영 상태
위치
간단한 거리 정보
```

저장된 수영장이 없을 때의
empty state도 제공한다.

---

## Important Rule

관심 수영장에서는
저장 당시의 상태가 아니라:

```text
현재 제공되는 오늘 상태
```

를 보여준다.

---

## Primary Actions

```text
수영장 상세 진입
관심 수영장 해제
같은 지역의 다른 수영장 검색
```

---

## Logged-out State

비로그인 사용자가 접근하면:

```text
로그인
→ 관심 수영장 목록으로 복귀
```

할 수 있어야 한다.

---

## Empty State

예:

```text
아직 저장한 수영장이 없어요.
```

다음 행동:

```text
수영장 찾기
```

를 제공한다.

---

# 7. Login

## Purpose

개인 상태가 필요한 기능을
안전하게 이용하도록 한다.

---

## Login Required Features

```text
관심 수영장 저장
후기 작성
정보 제보
마이페이지
```

---

## Entry Points

```text
관심 저장 선택
후기 작성 선택
정보 제보 선택
마이페이지 접근
```

---

## Core Information

```text
로그인 방식
회원가입 안내
기존 계정 안내
로그인 후 돌아갈 원래 화면 정보
```

---

## Primary Actions

```text
로그인
회원가입
로그인 취소
```

---

## Return Flow

로그인 성공 후
사용자가 원래 수행하던 작업으로 복귀한다.

예:

```text
수영장 상세
→ 관심 저장
→ 로그인
→ 같은 수영장 상세로 복귀
```

또는:

```text
후기 작성
→ 로그인
→ 같은 수영장 후기 작성 화면 복귀
```

로그인 성공만으로
후기 또는 제보를 자동 제출하지 않는다.

# 8. Pool Reports

---

## Entry Points

```text

```

미등록 수영장 등록 요청으로도 진입할 수 있다.

---

## Core Information

```text
제보 대상 수영장

제보 유형

현재 표시 중인 정보

수정 제안 입력

근거 입력

처리 상태 안내

운영자 검토 안내
```

---

## Report Types

예:

```text
자유수영 시간
가격
휴관
시설
미등록 수영장
기타
```

---

## Primary Actions

```text
로그인

제보 유형 선택

잘못된 정보 입력
수정 제안 입력

제보 제출
접수 완료 확인
```

---

## New Pool Request

미등록 수영장 등록 요청 시
다음 정보를 받을 수 있다.

```text

주소
또는 위치 정보
```

---

## Important Rule

제보 내용은
공식 정보에 자동 반영하지 않는다.

```text

→ 운영자 검토
→ 승인 또는 반려
→ 필요한 공식 데이터 수정
```

---

## Submit Failure

제출 실패 시:

```text
작성 내용 유지
오류 표시
재시도
```

를 제공한다.

---

예:

```text
검색 결과 없음
관심 수영장 없음
후기 없음
제보 없음
```

각 empty state에는
가능하면 다음 행동을 함께 제공한다.

---

## Error

예:

```text
네트워크 오류
조회 실패
저장 실패
등록 실패
```

실제 데이터가 없는 상태와
조회 실패를 구분한다.

---

## Unverified

정보가 확인되지 않은 경우:

```text
정보 미확인
```

으로 표현한다.

미확인을:

```text
이용 불가
```

로 바꾸지 않는다.

---

# 11. Common Information Rules

모든 화면에서 동일한 의미를 가진 정보는
가능하면 같은 표현을 사용한다.

예:

```text
오늘 자유수영 상태
남은 회차
다음 이용 가능 시간
가격
정보 최종 확인일
```

같은 상태를
화면마다 다른 기준으로 계산하지 않는다.

---

## Status Source

오늘 자유수영 상태는
화면에서 직접 계산하지 않는다.

```text
PoolService
→ 상태 계산
→ 화면에서 표현
```

검색 결과와 상세에서
서로 다른 상태가 표시되지 않도록 한다.

---

# 12. Navigation Principles

사용자가 현재 맥락을 잃지 않도록 한다.

예:

```text
검색 결과
→ 상세
→ 뒤로가기
→ 기존 검색 조건과 목록 상태 유지
```

로그인 역시 같은 원칙을 따른다.

```text
행동 시작
→ 로그인 필요
→ 로그인
→ 원래 화면으로 복귀
```

---

# 13. Screen Priority

1차 개발은 다음 순서로 진행한다.

```text
1. 홈
2. 수영장 검색 결과
3. 수영장 상세
```

이 세 화면으로 먼저:

```text
수영장 탐색
→ 오늘 자유수영 정보 확인
→ 방문 판단
```

흐름을 완성한다.

---

다음 단계:

```text
4. 로그인
5. 관심 수영장 목록
6. 후기 목록 및 작성
```

---

그 이후:

```text
7. 정보 제보
8. 마이페이지
```

를 연결한다.

---

# 14. MVP Screen Completion

핵심 탐색 화면이 완료되었다고 볼 수 있는 기준:

```text
사용자가 로그인하지 않아도

홈에서 수영장을 찾고

→ 검색 결과에서 후보를 비교하고

→ 상세에서 오늘 자유수영 상태,
   시간, 가격, 조건을 확인하고

→ 방문 여부를 판단할 수 있다.
```

개인화 기능은
이 핵심 경험이 동작한 뒤 추가한다.
