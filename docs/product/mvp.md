# SwimFind MVP

SwimFind MVP에서 해결하려는 핵심 문제와
우선 구현할 기능 범위를 정의한다.

새로운 기능을 추가하거나 구현 우선순위를 결정할 때
이 문서를 먼저 확인한다.

MVP의 목적은 수영 관련 기능을 많이 제공하는 것이 아니라,
사용자가 오늘 실제로 갈 수 있는 수영장을 빠르게 찾고
방문 여부를 판단할 수 있게 하는 것이다.

---

## 1. Core Problem

자유수영을 하려는 사용자는
주변에 어떤 수영장이 있는지는 지도 서비스를 통해 찾을 수 있다.

하지만 다음 질문에는 빠르게 답하기 어렵다.

```text
오늘 이 수영장에서 실제로 자유수영을 할 수 있는가?
```

수영장마다 다음 정보가 다르다.

```text
자유수영 운영 요일
자유수영 시간
이용 가격
휴관일
이용 조건
시설 정보
```

관련 정보도 여러 곳에 흩어져 있다.

예:

```text
수영장 공식 홈페이지
공지사항
블로그
지도 서비스
SNS
이용자 후기
```

특히 일반 시설 운영시간과
자유수영 가능 시간이 다른 경우가 많다.

따라서 사용자는 수영장을 찾은 뒤에도
여러 페이지를 확인하며 실제 방문 가능한지 판단해야 한다.

---

## 2. Problems to Solve

### Problem 1

오늘 자유수영이 가능한 수영장을 찾기 어렵다.

사용자가 원하는 것은 단순히:

```text
주변에 어떤 수영장이 있는가?
```

가 아니다.

핵심 질문은:

```text
오늘 내가 원하는 시간에
자유수영을 할 수 있는 수영장이 어디인가?
```

이다.

따라서 검색 결과 단계부터
오늘 이용할 수 있는 수영장을 빠르게 구분할 수 있어야 한다.

---

### Problem 2

수영장을 찾은 뒤에도
실제 방문 여부를 판단하기 위해 여러 정보를 따로 찾아야 한다.

사용자가 확인해야 하는 주요 정보:

```text
오늘 자유수영 운영 여부
자유수영 가능 시간
이용 가격
휴관 여부
이용 조건
위치
시설 정보
실제 이용 후기
```

SwimFind는 이 정보를 가능한 한 한곳에서 제공하여
사용자가 실제 방문 여부를 빠르게 판단할 수 있게 한다.

---

## 3. Core Value

SwimFind의 핵심 가치는 다음과 같다.

```text
오늘 갈 수 있는 수영장을
빠르게 찾을 수 있는 서비스
```

서비스가 가장 먼저 답해야 하는 질문:

```text
오늘 어디에서 수영할 수 있지?
```

핵심 사용자 경험:

```text
수영장 탐색
→ 오늘 자유수영 가능 여부 확인
→ 방문 결정
```

MVP에서는 다양한 수영 관련 기능을 제공하는 것보다
이 과정을 최대한 빠르고 편리하게 만드는 것을 우선한다.

---

## 4. Target Users

### Primary User

정기적으로 또는 가끔 자유수영을 하는 사람.

예:

```text
오늘 자유수영을 하려고 수영장을 찾는 사람

평소 다니던 수영장이 휴관해서
다른 수영장을 찾아야 하는 사람

원하는 시간에 자유수영이 가능한 곳을 찾는 사람

새로운 수영장을 경험해보고 싶은 사람

여행이나 외출 중 근처에서 수영할 곳을 찾는 사람
```

---

### Secondary User

새로운 수영 강습이나
수영장 정보를 탐색하는 사용자.

강습 정보도 수영장 선택에 유용하므로
수영장 상세 페이지에서 제공한다.

하지만:

```text
강습 전용 검색
강습 추천
```

은 MVP의 핵심 탐색 기능으로 두지 않는다.

---

## 5. Core User Flow

MVP의 가장 중요한 흐름:

```text
홈
→ 지역 또는 수영장 검색
→ 검색 결과
→ 수영장 상세
→ 오늘 자유수영 시간 / 가격 / 조건 확인
→ 방문 결정
```

사용자는 로그인하지 않아도
수영장 탐색과 상세 정보 확인이 가능해야 한다.

---

## 6. Core Feature A — Pool Discovery

오늘 갈 수 있는 수영장을 탐색하는 기능은
SwimFind에서 가장 중요한 기능이다.

홈 화면에서 바로 수영장을 찾을 수 있어야 한다.

포함 기능:

```text
수영장 이름 검색
지역 기반 탐색
오늘 자유수영 가능한 수영장 확인
간단한 조건 필터
수영장 목록
```

검색 결과는 단순한 수영장 목록이 아니라
오늘 이용 가능 여부를 비교할 수 있어야 한다.

---

### Pool Search Card

검색 결과 카드에서는 최소한 다음 정보를 제공한다.

```text
수영장 이름
대표 이미지
위치
오늘 자유수영 가능 여부
오늘 자유수영 가능 시간
```

예:

```text
OO국민체육센터

오늘 자유수영 가능
14:00 ~ 17:00

인천광역시 연수구
```

세부 표시 기준은:

```text
docs/product/ia.md
```

를 따른다.

---

## 7. Core Feature B — Pool Detail

수영장 상세 페이지는
사용자가 실제 방문 여부를 결정하는 핵심 화면이다.

페이지 상단에는
방문 판단에 가장 중요한 정보를 먼저 보여준다.

우선 정보:

```text
오늘 자유수영 가능 여부
오늘 이용 가능 시간
가격
위치
```

추가 정보:

```text
전체 자유수영 일정
운영시간
휴관일
이용 조건
시설
후기
FAQ
강습 정보
공식 홈페이지
```

정보가 많다고 해서
모든 정보를 같은 중요도로 한 번에 보여주지 않는다.

---

## 8. Core Feature C — Today's Free Swimming

오늘의 자유수영 정보는
MVP에서 가장 중요한 데이터다.

상세 화면을 열었을 때 사용자가 가장 먼저 알아야 하는 것은:

```text
오늘 이 수영장에서 자유수영을 할 수 있는가?
```

이다.

표시해야 하는 주요 정보:

```text
오늘 자유수영 가능 여부
이용 가능 시간
이용 가격
휴관 여부
이용 조건
```

예:

```text
오늘 자유수영

가능

14:00 ~ 17:00

성인 4,000원

현장 발권
입장 마감 16:30
```

확인되지 않은 정보는 추정하지 않는다.

예:

```text
입장 마감 시간 미확인
→ 임의의 시간 표시 금지
```

---

## 9. Core Feature D — Free Swimming Schedule

오늘뿐 아니라 다른 요일에 방문하려는 사용자를 위해
전체 자유수영 일정도 제공한다.

표시 정보:

```text
요일
이용 가능 시간
이용 가격
휴관일
특이사항
```

예:

```text
월 14:00 ~ 17:00
화 14:00 ~ 17:00
수 14:00 ~ 17:00
목 14:00 ~ 17:00
금 14:00 ~ 17:00
토 09:00 ~ 16:00
일 휴관
```

일반 운영시간과 자유수영 시간은
서로 다른 정보로 취급한다.

---

## 10. Core Feature E — Reviews

후기는 공식 정보만으로 알기 어려운
실제 이용 경험을 제공한다.

포함 기능:

```text
후기 목록
후기 작성
후기 작성자 프로필 확인
해당 사용자가 작성한 다른 후기 확인
```

후기에서 참고할 수 있는 정보 예:

```text
시설 청결도
레인 혼잡도
샤워실 상태
초보자 이용 경험
주차 및 접근성
실제 자유수영 이용 경험
```

후기는 탐색 자체의 핵심 기능이라기보다
방문 여부 판단을 돕는 정보로 사용한다.

---

## 11. Core Feature F — Favorites

사용자가 자주 방문하거나
나중에 다시 확인하고 싶은 수영장을 저장할 수 있게 한다.

포함 기능:

```text
관심 수영장 등록
관심 수영장 해제
저장한 수영장 확인
```

관심 수영장의 목적은
다시 검색하지 않고 오늘 자유수영 정보를 빠르게 확인하는 것이다.

---

## 12. Supporting Feature — Lesson Information

강습 정보는 수영장 상세 화면의
보조 정보로 제공한다.

표시할 수 있는 정보:

```text
강습 종류
요일
시간
가격
모집 관련 정보
```

상세 페이지의 정보량이 지나치게 많아지지 않도록
별도 영역이나 펼쳐보기 형태를 사용할 수 있다.

MVP에서는 다음 기능까지 구현하지 않는다.

```text
나에게 맞는 강습 찾기
```

---

## 13. Supporting Feature — Pool Reports

자유수영 일정이나 수영장 정보가
오래되었거나 실제 정보와 다른 경우
사용자가 정보를 제보할 수 있다.

기본 흐름:

```text
사용자 제보
→ 검토 대기
→ 운영자 확인
→ 승인 또는 반려
→ 승인된 경우 공식 정보 별도 수정
```

사용자 제보가 즉시 공식 정보에 반영되지 않는다.

검증되지 않은 제보를
수영장 상세에서 공식 정보처럼 표시하지 않는다.

---

## 14. Authentication Boundary

로그인하지 않아도 사용할 수 있는 기능:

```text
수영장 탐색
검색 결과 조회
수영장 상세 조회
후기 조회
```

로그인이 필요한 기능:

```text
관심 수영장 저장
후기 작성
정보 제보
마이페이지
```

로그인이 핵심 탐색 경험을 막지 않도록 한다.

---

## 15. Out of Scope

첫 번째 버전에서는 다음 기능을 구현하지 않는다.

```text
강습 전용 검색 및 추천
강습 신청 및 결제
수영장 예약

수영 기록 관리
운동 기록 통계

친구 추가
사용자 팔로우
DM
사용자 간 채팅

커뮤니티 게시판
수영 모임 모집

수영 대회 정보
수영 팝업 정보

실시간 혼잡도
실시간 레인 현황

강사 리뷰

수영용품 쇼핑
수영용품 장터
```

이 기능들은 출시 이후
실제 사용자 요구를 확인한 뒤 확장 여부를 검토한다.

---

## 16. Feature Priority

MVP 기능은 다음 우선순위를 따른다.

### Priority 1 — Core Discovery

```text
홈
수영장 검색
검색 결과
수영장 상세
오늘 자유수영 상태
자유수영 일정
가격 / 휴관 / 이용 조건
```

이 단계만으로도 사용자는:

```text
오늘 어디에서 수영할지 결정
```

할 수 있어야 한다.

---

### Priority 2 — Personalization

```text
로그인
관심 수영장
```

핵심 탐색 경험이 동작한 뒤 연결한다.

---

### Priority 3 — User Experience Information

```text
후기 조회
후기 작성
```

사용자의 방문 판단을 보완한다.

---

### Priority 4 — Data Quality

```text
정보 제보
운영자 검토
```

서비스 데이터의 신뢰도를 개선한다.

---

## 17. MVP Success Criteria

첫 번째 버전에서는
단순한 가입자 수보다 다음 질문을 더 중요하게 본다.

```text
사용자가 실제로 오늘 갈 수 있는 수영장을 찾을 수 있었는가?
```

확인할 주요 지표:

```text
홈에서 수영장 탐색을 시작하는 비율

검색 결과에서
수영장 상세 페이지로 이동하는 비율

오늘 자유수영 정보를 확인하는 비율

관심 수영장 저장 비율

후기 열람 비율

재방문 사용자 비율
```

핵심 전환 흐름:

```text
수영장 탐색
→ 오늘 자유수영 가능 여부 확인
→ 수영장 상세 확인
```

궁극적인 성공 기준은 사용자가 서비스를 이용한 뒤:

```text
오늘 어디서 수영할지 결정할 수 있었다.
```

라고 느끼는 것이다.

---

## 18. Product Decision Rule

새로운 기능을 제안하거나 구현하려 할 때
다음 질문을 먼저 확인한다.

```text
이 기능이 사용자가
오늘 갈 수 있는 수영장을 찾는 데 직접 도움이 되는가?
```

직접적인 도움이 된다면
MVP 우선순위를 검토한다.

그렇지 않다면
MVP 이후 기능으로 미룰 수 있는지 먼저 검토한다.

---

## 19. Core Principle

SwimFind MVP의 목적은
수영 관련 모든 문제를 해결하는 것이 아니다.

가장 먼저 해결해야 하는 경험은:

```text
수영장을 찾는다
→ 오늘 자유수영 가능한지 확인한다
→ 필요한 가격과 조건을 확인한다
→ 방문할 곳을 결정한다
```

이다.

기능 수보다 이 핵심 흐름의
속도, 명확성, 신뢰성을 우선한다.
